## 1. Correcting the premise: `docs/index.html` was never generated

The work order said `docs/` is generated by `scripts/generate_website.py` and warned that
hand-editing `docs/` would be erased by the next render. **That is true of every page
except the one this task is about.**

`generate_website.py` writes `docs/records/`, `docs/top10/` and `docs/annual/`. It never
wrote `docs/index.html`. `grep -n "index.html" scripts/generate_website.py` returns only
two `href` occurrences inside the nav literal, and `main()` has no call that touches it.
`CLAUDE.md` agrees: *"Splash/Home | `docs/index.html` | Manual"*.

So the landing page had no generator to change. Rather than hand-write 400 lines of HTML
that the next person would have to hand-maintain too, **I gave it one**:

* `data/season_2026-27.json` — new. Schedule, roster, and the record facts, each with a
  `_source` field naming where it came from and when it was fetched.
* `scripts/generate_landing_page.py` — new. Renders `docs/index.html` from that JSON plus
  `records/records-boys.md`.
* `scripts/generate_website.py` — now invokes it, the same way it already invokes
  `rebuild_relay_pages.py` and `generate_annual_pages.py`.

The work order's intent — *don't put facts somewhere a render will erase* — is honoured.
Its stated mechanism was based on a premise that did not hold for this file.

`docs/seniors/class-of-2026.html` remains hand-maintained, exactly as it was as
`index.html`. It is a fixed historical record of one graduating class; there is nothing
for a generator to recompute.

### Two details that would have been easy to get wrong

* **All-day end dates in `events.json` are exclusive.** The State entry reads
  `2026-11-06 → 2026-11-08`; that is **Nov 6–7**, not Nov 6–8. Confirmed against the
  BOARD's independent "Nov 6-7" and against the Regional entry, whose description says
  "Fri+Sat" and whose range `10-23 → 10-25` therefore means Oct 23–24. Reading those ends
  as inclusive would have put a wrong date on a school page.
* **Start times are deliberately absent.** The source explicitly says no start time is
  published for the Oct 17 and Nov 6–7 meets. The page prints no times at all and tells
  readers to confirm with the coaching staff rather than inventing a 16:00 default.

azpreps365 was **not** consulted. It was offered only as a cross-check against a schedule
that could not be verified; the primary source was found, is the school's own sheet, and is
strictly better than a third-party aggregator. Nothing was reconstructed from a prior season.

### ⚠️ One discrepancy, flagged rather than smoothed over

The schedule shows **three** meets on or before today (Sep 3, Sep 10, Sep 19). MaxPreps has
published results from **one** (the Sep 19 CDO Classic), which is what PR #2 imported.

A scheduled meet is not proof a meet was swum, and absence from MaxPreps is not proof it
was not. So the page claims only what is provable: *"Results have been published from one
meet so far."* It does not say one meet has been swum, and it does not say three have.
**Worth Aaryn's attention:** if Sep 3 and Sep 10 were swum, those results are missing from
MaxPreps and the 2026-27 Top 10 is incomplete in a way nobody would notice from the page.

The 2015 mark was the oldest, and not marginally: the **next-oldest is six years younger**.
It was the only boys record predating 2021.

**The check is code, not a claim in a document.** `verify_oldest_record()` in
`scripts/generate_landing_page.py` re-derives this on every build and returns one of
`oldest` / `not-oldest` / `unverifiable`. The page's wording is chosen from that verdict:
if an older record is ever added to `records/`, the sentence **automatically downgrades** to
"one of the longest-standing" and names whichever record is actually oldest. The superlative
cannot silently become false. Build output:

```
oldest-record check: oldest -> "the oldest record on the Tanque Verde boys books"
next-oldest standing boys record: 50 Freestyle (Oct 23, 2021)
```

**Scope stated honestly on the page.** The claim is rendered as *"the oldest record on the
Tanque Verde boys books"* rather than a bare "oldest record". What was verified is the boys
side — Aaryn said "men's" — and the sentence says exactly that. The girls records were not
examined and the page makes no claim about them.

## 6. Validation (Rule 4)

### Determinism — passes, across all 120 pages

```
$ python3 scripts/generate_website.py   # run 1
$ find docs -name '*.html' | sort | xargs shasum -a 256 > /tmp/r1.txt
$ python3 scripts/generate_website.py   # run 2
$ find docs -name '*.html' | sort | xargs shasum -a 256 > /tmp/r2.txt
$ diff /tmp/r1.txt /tmp/r2.txt && echo OK
OK — 120 files byte-identical
```

Baseline established first: `generate_website.py` was run on the **untouched base branch**
and left `docs/` with an empty `git status`, so the committed output was already in sync and
this PR's `docs/` changes are all attributable to this PR.

The new generator introduces no new nondeterminism: no `set` or `dict` iteration over
unordered input, no filesystem-order globbing, no randomness. It uses `datetime.now()` only
in the footer, matching `generate_website.py`'s existing convention exactly.

### No record value changed

All 43 regenerated pages under `docs/records/` and `docs/top10/` are **+4 / −0**. The
complete set of unique added lines across all of them:

```
+  <a class="nav-link" href="/seniors/class-of-2026.html" id="nav-seniors" …>🎓 Seniors</a>
+  </li>
+  <li class="nav-item">
+  <li><a class="dropdown-item season-link" data-path="top10" href="#">2026-27</a></li>
```

Nav only. **Zero deleted lines** (`git diff … | grep -cE '^-[^-]'` → `0`), so no time, name,
date or meet moved. `records/`, `data/class_records_history.json` and the relay data are
untouched by this PR — `git status` shows no modification to any of them.

The 2026-27 Top-10 entry is a fix, not a regression: PR #2 created

## 7. Design

Plain semantic HTML with Bootstrap 5 utility classes, rendered from Python — identical to
every other page on the site. **No framework, no build step, no external fonts, no new CDN
asset.** The one CDN reference (`bootstrap@5.3.0`) is the same `<link>` every existing page
already carries; nothing new was introduced.

Phone-readable: the schedule is in `.table-responsive`, senior cards are `col-6 col-md-4`
(two per row on a phone, three on a desktop), and record cards are `col-md-6` so they stack.
The nav, collapsible hero, section toggles and footer follow the conventions
`generate_website.py` already emits.
